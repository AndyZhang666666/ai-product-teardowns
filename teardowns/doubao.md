# 字节豆包 拆解

**拆解日期**：2026-09
**体验方式**：iOS App + 网页端免费账号，日常使用约两个月，另做了约 20 组对照测试
**一句话结论**：它把多模态做成了默认交互而非功能入口，但最大的产品难题不是能力，是「用户不知道该期待什么」。

---

## 1. 目标用户与场景

**服务的时刻**：一个没形成 AI 使用习惯的普通人，遇到具体小麻烦时（题不会讲、PDF 太长、外语看不懂）随手问一句。它优化的是从产生念头到得到答案的路径长度，不是答案的天花板——证据是交互重心全在压缩启动成本：按住即说、拍照直接问、划词唤起。

**谁不在用户群里**：需要稳定复现结果的专业工作流用户。它的形态是对话，对话不可版本管理。一个要「同一提示词跑一百次、对比效果、固化成模板」的人在这里没有工具支撑。另一类是对信息来源有强审计要求的人。

## 2. 能力边界

**做得对的**：图片理解最稳（拍题、表格截图、手写笔记的识别与结构化提取，测试中没失手）；长文档提取要点稳定；口语化改写质量高。

**开始退化的条件**：

- **多步精确计算会中途出错，且出错时叙述依然流畅。** 给它一组销售数据算复合增长率，公式正确、中间步骤正确、最后一步数值算错，但结论写得很确定。**过程正确性掩盖了结果错误性**——用户看到步骤都对就不验算了。
- **联网检索质量取决于问题的「可搜索性」。** 有明确出处的问题答得准；需要综合判断的（某行业今年趋势）它会搜到几篇观点文章当成事实综合，看起来有依据实际是二手观点的平均。
- **多轮对话中指令衰减。** 第一轮设定「都用表格」，五六轮后悄悄退回散文，不会说「我忘了」，就是不做了。

**一个可验证的例子**：问「2026 上半年国内 AI 领域值得关注的融资」，它给出带公司名、金额、投资方的整齐清单。抽查三条，两条能对上公开报道，一条金额不一致。**清单形式本身传递了「已核实」的暗示，实际并没有。** 排版越整齐，这个暗示越强。

## 3. 实现路径推测

> 以下为推测，依据为外部线索。

**推测**：多模型路由 + 按模式分层的推理深度 + 检索增强。不是单一模型支撑所有场景。

**依据**：不同类型问题的首 token 延迟呈**离散档位**而非连续分布——离散是路由的典型特征。产品自己把推理深度分层显式化了，等于承认不同深度对应不同成本。涉及时效信息时，空白期结束后文字连贯吐出、中间不停顿——检索发生在生成前而非生成中。

**对产品判断的影响**：如果路由存在，**体验方差主要来自路由判断的准确性，而非模型能力**。本该走深度推理的问题被路由到快速通道，用户看到的就是「豆包变笨了」。这解释了实际感受：同一类问题在不同时候的质量差异，比不同类问题之间的差异更大。而用户完全无法感知路由发生了什么。

## 4. 失败与兜底

**错的时候长什么样**：语气、格式、置信度全都不变。上面融资清单里错的那条和对的两条在呈现上无法区分。

**兜底做得好的**：深度模式给出检索来源可点开核对——这是真兜底。

**兜底缺失的**：「AI 生成可能有误请核实」是**全局免责，不是针对具体内容的不确定性提示**。它对每句话说同样的话，等于对每句话都没说。更关键的是**没把「用了检索、有来源」和「纯靠模型记忆」区分开**——两者风险差一个数量级，界面上长得一样，用户没有线索判断该不该核实。

## 5. 效果怎么衡量

通用助手最难定指标，因为**它没有单一任务**。做法是先按意图分层，再在层内定指标。

| 类别 | 指标 | 为什么 |
|---|---|---|
| 使用类 | 日活、人均日会话数、**多模态入口使用占比** | 第三个是差异化，单独看 |
| 质量类 | **追问率**（同会话内为同一意图再次发问） | 见下 |
| 质量类 | **会话内放弃率**（提问后不再交互直接关闭） | 失败的沉默信号 |
| 质量类 | 复制/分享/导出率 | 答案被拿去用了 |
| 价值类 | 回访率按意图类型拆分、付费转化前的行为路径 | 哪类需求真正留人 |

**为什么追问率是核心**：唯一不需要标注就能大规模反映「答案不够好」的信号，且能按意图分层定位短板。但它有陷阱——**追问也可能是答得好、用户想深入**。所以必须和放弃率一起看：追问高+放弃低 = 用户在深挖（好）；追问高+放弃高 = 用户在挣扎（坏）。单看任何一个都会误判。

**最缺的是路由准确性的可观测性。** 存在路由就存在「路由错了」这种失败模式，但要衡量它，得先有「这问题本该走哪条路」的标注，而这需要人工。典型的「最重要的指标最难埋」。

## 6. 商业化路径

**付费门槛**：卡在高消耗动作次数（图片视频生成、深度模式、长文档）和高峰期优先级上，日常问答基本不设限。

**免费额度意图**：拉新且培养习惯，免费能力宽度远超同类——先占入口，不是先赚钱。

**是否对齐**：**比可灵好，但有结构性问题。** 对齐的部分是付费解锁「更多次数」和「更快」，用户在被限制的当下立刻感知需求，时机准。

结构性问题：**免费版足够好，是获客优势也是转化障碍。** 普通用户永远碰不到付费墙，付费用户被压缩到少数重度用户——而这批人最会算成本、最容易流向 API 或竞品。所以它真正要解决的不是「怎么让人付钱」，而是「怎么让普通用户产生高价值需求」。这解释了产品为什么持续往办公任务、PPT、表格长——**这些不是能力扩张，是在制造付费场景。**

## 我不同意的地方

**不同意把不确定性处理成一句全局免责声明。** 用户三天就脱敏，之后它只承担法律责任，不承担产品责任。

而产品明明有能力做得更好：它内部知道这次有没有走检索、有没有拿到来源。**这些信息是已知的，只是没告诉用户。** 这不是技术限制，是产品选择——大概担心显示「本次未检索」会让用户觉得产品不行。

我认为这个担心是错的。**用户对 AI 的信任不建立在「它总是对」，而建立在「我知道什么时候该信它」。** 永远自信的助手，用户被坑一次就全面降级信任；会说「这次不太确定」的助手，用户会学会分场景使用——后者长期使用深度更高。

## 我会做的下一步

1. **给回答加「依据来源」分类标签而非免责声明**，三档：带检索来源（可点开）、基于模型知识（提示时效风险）、需要计算（建议验算）。信息系统内部已有，成本主要在 UI。验证：带来源标记的回答采纳率是否显著高于无标记——是则说明标记在帮用户决策，而不是制造焦虑。

2. **多步计算类任务强制加一步独立验算。** 上面算错的例子，用同一模型再算一遍比对，成本翻倍 token 但能抓住大部分算术错误。我在做评估工具时验证过一个相关结论：同一模型对同一内容的多次判断存在方差（见 [llm-output-eval](https://github.com/AndyZhang666666/llm-output-eval) 的一致性检查），而这个方差恰好可以用来交叉验证——两次算出同一个数，比一次可信得多。

## 局限说明

基于免费账号的外部观察，未覆盖付费版与企业版。实现路径为推测，依据是延迟分布、模板化程度这类外部线索。效果指标是我假设的 PM 视角。不写具体价格数字。
